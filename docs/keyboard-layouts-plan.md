# План: многоязычные раскладки клавиатуры

Рабочий документ по итогам обсуждения в [PR #2828](https://github.com/crosspoint-reader/crosspoint-reader/pull/2828). Не коммитить в upstream — это заметки для себя.

## Откуда взялось

PR #2828 добавлял ЙЦУКЕН прямо в прошивку (`KeyboardEntryActivity`) и клавишу РУС/ABC. Uri-Tauber отклонил подход и задал рамку:

> Additional layouts should live in the SDK.

> I do like the idea of switch-lang key. Although it should be more general than russian-english only. My thinking was to allow switching between English layout and current language layout. So, for example, if your UI lang is Hebrew, you could switch between English and Hebrew. Same for Arabic, Russian, and any other languages. It will be a bigger SDK change than what you planned here — essentially adding a dozen of new layouts. The firmware side will be to show the correct layouts alone (Arabic user don't have any use for Russian layout).

> I planned to do it myself in the near future, but feel free to take it on yourself.

Сверху я предложил расширение: пары «UI-язык + English» мало, если читаешь на третьем языке (UI русский, книги испанские). Отсюда — опциональный набор включённых раскладок и циклическое переключение вместо тумблера. Uri-Tauber на это ещё не ответил.

**Решение (2026-08-03): делаем сами.** Работа идёт в отдельной ветке и не попадает в открытые PR, пока не будет готова целиком. Uri-Tauber писал «feel free to take it on yourself» — этого достаточно, чтобы начать; о том, что взялись, сообщим ему до того, как он начнёт сам.

**Обязательное требование (не опция):** пользователь должен иметь возможность включить любую раскладку по своему желанию. Пара «язык интерфейса + English» — только дефолт, а не потолок. Причина из практики: интерфейс на русском, книги на испанском — испанская раскладка нужна для поиска в OPDS и имён файлов. Язык чтения не обязан совпадать ни с языком интерфейса, ни с английским. Это влияет на модель хранения (набор, а не пара) и на поведение клавиши (цикл, а не тумблер) — то есть закладывается с самого начала, а не прикручивается потом.

## Как устроено сейчас

### SDK (`freeink-sdk/libs/ui/FreeInkUI`)

`include/components/keyboard/keyboard.h`:

```cpp
enum class KeyboardLayoutId : uint8_t {
  QwertyEn,
  AzertyFr,
  QwertzDe,
  SpanishEs,
};

const KeyboardLayout& builtinKeyboardLayout(KeyboardLayoutId id, bool shifted = false,
                                            bool symbols = false, bool numberRow = false);
const char* keyboardOutputFor(const KeyboardLayout& layout, int16_t value);
const char* keyboardAltOutputFor(const KeyboardLayout& layout, int16_t value);
```

Таблицы рядов — в `src/FreeInkUI.cpp` (`EN_ROW1`, `NUM_ROW`, макросы `K`/`K2`/`KS`/`KA`). Все `static const` → флеш.

`KeyKind` (`key-grid.h`): `Normal, Shift, Mode, Space, Delete, Ok, Disabled`. Отдельного вида для переключения языка **нет** — это ключевая нехватка.

### Прошивка (`src/activities/util/KeyboardEntryActivity.cpp`)

```cpp
fui::KeyboardLayoutId layoutForLanguage(const Language language)   // :112
layoutId = inputType == InputType::Url ? QwertyEn : layoutForLanguage(...)   // :132
```

То есть выбор раскладки уже завязан на язык интерфейса, а URL-поля всегда латиница. Каркас под задачу есть.

## Что делать

### Этап 1 — SDK: новые раскладки

Расширить `KeyboardLayoutId` и добавить таблицы рядов. Дюжина, как сказал Uri-Tauber. Приоритет — языки, у которых уже есть перевод интерфейса и нелатинская письменность:

| Раскладка | Язык UI | Замечания |
|---|---|---|
| `CyrillicRu` | русский | ЙЦУКЕН; таблицы уже написаны в PR #2828, переносятся почти как есть |
| `CyrillicUk` | украинский | ЙЦУКЕН + `і ї є ґ`, ряды длиннее русского |
| `CyrillicBe` | белорусский | + `ў`, нет `и щ ъ` |
| `CyrillicKk` | казахский | + `ә ғ қ ң ө ұ ү һ і` — самый широкий ряд, 12+ клавиш |
| `HebrewIl` | иврит | RTL, см. риски |
| `ArabicSa` | арабский | RTL + контекстные формы букв |
| `GreekGr` | греческий | если появится перевод |

Что учесть при переносе из #2828:

- id клавиш = кодовая точка Unicode буквы (U+0410..U+044F), влезает в `int16_t`, не конфликтует ни с ASCII-ид, ни с отрицательными служебными, ни с URL-сниппетами (2001+)
- `alt` для длинного нажатия задавать явно — SDK умеет автоматически флипать регистр только для ASCII `a-z`/`A-Z`
- исключение: долгое нажатие `е`/`Е` даёт `ё`/`Ё`, потому что у `ё` нет своей клавиши в ЙЦУКЕН

### Этап 2 — SDK: клавиша переключения языка

Нужен новый `KeyKind::Lang` (или переиспользовать `Mode` со вторым значением — решать вместе с Uri-Tauber). Требования:

- метку рисует приложение через `KeyboardProps` — SDK не должен знать, какая раскладка следующая
- SDK сообщает нажатие через `ActionEvent`, приложение само меняет `layoutId`
- при переключении сбрасывать `shifted`, иначе на новой раскладке залипнет верхний регистр

### Этап 3 — прошивка: выбор набора раскладок

Дефолт по Uri-Tauber: **раскладка языка интерфейса + English**. Ноль настроек, работает сразу.

Поверх этого — настраиваемый набор, требование обязательное:

- битовая маска включённых раскладок в `CrossPointSettings` — `uint16_t` покрывает 16 штук
- экран настроек со списком всех раскладок, которые есть в SDK; пользователь отмечает нужные
- клавиша языка циклически идёт по включённым; при дефолтных двух ведёт себя ровно как тумблер, так что для не открывавших настройки ничего не меняется
- метка показывает код следующей раскладки в цикле: `EN` → `RU` → `ES`
- дефолт вычисляется при первом запуске из языка интерфейса, дальше живёт как пользовательская настройка

Стоимость по RAM нулевая: таблицы `const` лежат во флеше независимо от того, включены они или нет. Включение раскладки не выделяет ни байта — меняется только бит в маске.

Правило Uri-Tauber «арабскому пользователю не нужна русская раскладка» при этом соблюдается: по умолчанию не показывается ничего лишнего, набор расширяется только явным действием пользователя.

### Этап 4 — прошивка: правила показа

- URL-поля остаются латиницей всегда (как сейчас, `:132`)
- поля паролей и логинов стартуют с латиницы — Wi-Fi пароли и имена почти всегда ASCII
- текстовые поля стартуют с раскладки языка интерфейса
- `InteractionBuffer<48>` → `<56>`: ЙЦУКЕН регистрирует 48 прямоугольников против 41 у EN. Для казахского пересчитать заново, там ряды шире

### Что готово

**Девять раскладок.** Латиница: `QwertyEn`, `AzertyFr`, `QwertzDe`, `SpanishEs`. Кириллица: `CyrillicRu`, `CyrillicUk`, `CyrillicBe`, `CyrillicKk`. Плюс `HebrewIl`.

**Клавиша переключения** — новый `KeyKind::Lang` в SDK, id `QWERTY_KEY_LANG = -4` (−3 занят `URL_PANEL_KEY` в прошивке). Метка приходит из приложения через `KeyboardProps::langLabel` и показывает **текущую** раскладку. Флаг `langKey` в `builtinKeyboardLayout` делает клавишу опциональной, чтобы односкриптовые сборки выглядели как раньше.

**Верхний регистр** есть у всех, где он существует. У FR/DE/ES его не было вовсе — клавиша `Shift` рисовалась, но ничего не делала.

**Настройка набора** — `CrossPointSettings::keyboardLayouts`, битовая маска `uint16_t`. Ноль означает «не настроено» и даёт язык интерфейса + English. Экран выбора: Настройки → Система → Раскладки клавиатуры (`KeyboardLayoutsActivity`).

**Логика набора** вынесена в `src/activities/util/KeyboardLayoutSet.{h,cpp}`: дефолт, порядок цикла, коды ISO 639-3, фильтрация битов несуществующих раскладок, `startingLayout()`.

### Найденные и исправленные дефекты

1. **Дубли на клавишах** — явные `alt` у каждой кириллической буквы рисовались подсказкой в углу («йЙ»). Решено расширением case-flip в SDK на кириллицу; явных `alt` осталось два (`е`→`ё`, `Е`→`Ё`).

## Риски

**Арабский отложен (2026-08-03).** При попытке добавить выяснилось, что во встроенных шрифтах SDK **нет базовых арабских букв** (U+0622..U+064A) — есть только `U+0621`, презентационные формы `U+FE80..U+FEFC` и арабские цифры. При этом `arabic.yaml` хранит текст базовыми буквами (`جاري التحميل` — 11 базовых, ноль презентационных), то есть между строкой и экраном работает шейпер.

Для клавиатуры отсюда развилка, которую надо разрешать опытом:
- положить на клавиши базовые буквы и проверить, проходит ли метка клавиши через тот же шейпер — если да, покажется изолированная форма и всё просто;
- иначе класть в `label` презентационную форму, а в `output` базовую, что требует ручного сопоставления 36 букв и удваивает таблицу.

Иврит таких вопросов не поставил: его буквы есть в шрифте как есть, контекстных форм нет.

**RTL.** Иврит и арабский — не просто другие буквы. Нужна проверка, что рендер клавиатуры и поле ввода не ломаются на смешанном тексте. В прошивке есть MiniBidi, но как он поведёт себя в поле ввода с курсором — не проверял. Арабский вдобавок требует контекстных форм букв (начальная/срединная/конечная), и если SDK-шрифты их не содержат, клавиши покажут изолированные формы.

**Ширина рядов.** Казахский, украинский и русский в верхнем ряду имеют 11-12 букв против 10 у QWERTY. На 480 px это уже тесно; на мелких панелях (Murphy M3, 240 px) не влезет вовсе. Нужно решить, что делать — уменьшать клавиши или переносить буквы во второй слой.

**Размер прошивки.** Дюжина раскладок — это дюжина наборов таблиц во флеше. Оценить рост бинарника до того, как писать все; если критично, обсудить условную компиляцию по языкам.

**Параллельная работа.** Uri-Tauber писал «I planned to do it myself in the near future». Риск дубля снимается тем, что мы сообщим ему о начале работы — но сделать это надо раньше, чем он возьмётся, иначе выкинуть придётся чью-то работу.

**Форк SDK.** `freeink-sdk` подключён как submodule на `Free-Ink/freeink-sdk`. Прав на пуш туда нет, форка пока нет — понадобится, как для симулятора.
