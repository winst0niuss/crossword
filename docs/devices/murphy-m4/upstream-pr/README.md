## Что именно мы им даём

Их репозиторий разбирает `murphy-26-0526-1.2.16.bin`. Заводская линейка с тех пор ушла вперёд:
текущий OTA-релиз — **Panda AI OS**, и он, в отличие от 1.2.16, **печатает всю свою аппаратную
конфигурацию в лог при загрузке** через `printf`-строки, которые остались в бинаре. То есть пинаут
M4 читается с serial-консоли стокового устройства, без реверса.

Разбор call-site этих логов даёт:

1. **Независимое бинарное подтверждение всех их пинов**, добытых щупами: дисплей 3/4/5/6/7/8, тач
   13/12/44/45 по адресу `0x2E` с active-LOW питанием, SD 16/15/17/18/11/14 с явным
   `gpio_set_level(10, 0)`, батарея на GPIO9, фронтлайт cool 47 / warm 48, буфер 480×800 логический
   с транспонированием на панель 800×480. Плюс бустер SSD1677 и gate=479 — подтверждают их
   определение контроллера по второму, более новому образу.
2. **Новое, чего у них нет:**
   - **card detect на GPIO21** (вход с подтяжкой, `gpio_get_level(21)`) — в их `hardware.md`
     такой линии нет вообще, порт её не использует;
   - заводские частоты: **шина SD 20 МГц** против 400 кГц в порте, **PWM фронтлайта 5 кГц**
     против 25 кГц;
   - адрес и частота I²C тача из констант: `0x2E`, 400 кГц;
   - датчики среды: пробы `AHT30`, `AHT20` по `0x38`, `SHT40` по `0x44`/`0x45` (на железе не
     проверялось, так и написано);
   - полный OTA-манифест (`version`, `app_offset`, `product`, `board`, `sha256`) — у них он описан
     как содержащий только `firmware_url` и `firmware_size`.

## Чего сознательно НЕ отдаём

Из наших заметок выброшено всё, что устарело или было пересказом их же выводов:

- «официального порта M4 нет», «дампа никто не снимал» — у них давно рабочий порт на живом
  устройстве;
- «контроллер панели неизвестен» — они определили SSD1677 по init-последовательности;
- оговорка про сомнительный порядок D0–D3 — снята, извлечённые пины совпали с их замером;
- «1.2.16 не содержит признаков модели, значит принадлежность к M4 — заявление авторов» — теперь
  есть подтверждение железом;
- вся часть про M3, upstream-PR, лицензии, продавцов и цены — не их тема.

## Проверка находок

Все константы получены дизассемблированием, а не доверием к прошлым заметкам:

```bash
cd docs/devices/murphy-m4
python3 upstream-pr/tools/find_string_refs.py firmware/panda-ai-os-2.3.5.bin "SD card detect GPIO"
upstream-pr/tools/xtensa_ctx.sh firmware/panda-ai-os-2.3.5.bin 0x4201f8e9 60 16
```

Нужен `xtensa-esp32s3-elf-objdump` — он уже стоит вместе с PlatformIO
(`~/.platformio/packages/toolchain-xtensa-esp-elf/bin/`). Ghidra и capstone не нужны; их
собственный `tools/esp32s3_xtensa_disasm.py` требует сборку capstone с бэкендом Xtensa, которой в
released capstone 5.x нет (`CS_ARCH_XTENSA` отсутствует).

Образы 2.2.7 и 2.3.5 разобраны оба и совпадают по всем константам. В 2.3.5 значения даже полнее:
адрес тача стал компайл-тайм константой, а питание SD видно как явный `gpio_set_level(10, 0)`.

## Как применить в их репозитории

```bash
git clone https://github.com/crosspoint-reader/Murphy.git
cd Murphy && git checkout -b m4-panda-ai-os-analysis
cp <путь>/panda_ai_os.md m4/findings/
cp <путь>/tools/* tools/
cp <путь>/../firmware/panda-ai-os-2.3.5.bin m4/
git am < <путь>/existing-docs.patch   # правки в существующих документах
```

`existing-docs.patch` содержит только текстовые правки; новые файлы и образ копируются отдельно,
чтобы не тащить 4.3 МБ бинаря через base85 в патче.
