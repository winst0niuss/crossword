# Инструменты разбора прошивок Murphy

Три маленьких скрипта, которыми из образа `panda-ai-os-2.2.7.bin` вынули распиновку
(см. [../firmware-analysis.md](../firmware-analysis.md)). Те же скрипты применимы к дампу
собственного устройства, когда оно приедет.

Ghidra не нужна: в PlatformIO уже есть `xtensa-esp32s3-elf-objdump`
(`~/.platformio/packages/toolchain-xtensa-esp-elf/bin/`).

## `espimg.py` — структура образа

```bash
python3 espimg.py panda227.bin
```

Разбирает заголовок ESP32-приложения: chip id, точку входа, все сегменты с адресами загрузки
(DROM / IROM / IRAM / DRAM), затем находит заданные строки и литералы, ссылающиеся на них.

Список искомых строк — в константе `TARGETS` внутри файла.

## `findl32r.py` — поиск обращений к строке

```bash
python3 findl32r.py
```

Линейный дизассемблер на сыром бинарнике рассинхронизируется (у Xtensa инструкции переменной
длины и код перемешан с данными), поэтому ссылки ищутся **арифметически**: перебираются все
возможные PC, и для каждого проверяется, кодируют ли байты `l32r` с нужным смещением.

`l32r at, label`: `byte0 = (at<<4)|0x1`, `byte1 = imm & 0xff`, `byte2 = imm >> 8`,
адрес цели `= ((PC+3) & ~3) + (imm - 0x10000) * 4`.

Адреса сегментов зашиты в `SEGS` — при работе с другим образом обновить по выводу `espimg.py`.

Важно: форматные строки часто начинаются с `%s ` (тег). Искать надо адрес **начала** строки,
иначе ссылка не найдётся — на этом уже спотыкались.

## `ctx.sh` — дизассемблер вокруг адреса

```bash
./ctx.sh 0x42027f79 96 24     # <PC> [байт до] [байт после]
```

Подбирает согласованную точку старта (перебирает смещения назад, пока цепочка инструкций не
попадёт ровно в PC) и печатает окрестности. Ожидает рядом `irom.bin` — сегмент IROM,
вырезанный из образа по данным `espimg.py`.

## Как читать результат

Вызовы логов идут через `call8`, поэтому аргументы функции лежат в `a10`–`a15`, а всё сверх
шести — на стеке:

| Аргумент | Где |
|---|---|
| 0 | `a10` — уровень лога |
| 1 | `a11` — тег |
| 2 | `a12` — форматная строка |
| 3, 4, 5 | `a13`, `a14`, `a15` |
| 6, 7, 8, … | `[a1+0]`, `[a1+4]`, `[a1+8]`, … |

Значения кладутся инструкциями `movi` / `movi.n` незадолго до вызова. Осторожно: регистры
переиспользуются, а часть `s32i` пишет не аргументы, а поля структуры конфигурации —
сверяться нужно по смещению стека, а не по порядку строк.
