# Из чего состоит электронная книга и что из ПО у нас уже есть

Простым языком: что за железки внутри Murphy M4, зачем каждая нужна, и для каких из них
код уже написан другими, а для каких придётся писать самим.

## 2. Что делает каждая часть

| Часть | Простыми словами | Как подключена |
|---|---|---|
| **ESP32-S3** | Главный чип. Выполняет прошивку: читает книгу с карты, раскладывает текст по страницам, рисует их на экране | — |
| **Флеш 16 МБ** | Встроенная память, где лежит сама прошивка. Книги сюда не пишутся | внутри чипа |
| **Экран e-ink** | Картинка держится без питания; чтобы её сменить, надо «прокачать» пиксели по особому рецепту | 6 линий SPI |
| **Тачскрин** | Отдельная микросхема поверх экрана: сообщает координаты пальца | 4 линии I²C |
| **SD-карта** | Тут лежат книги, шрифты и кеш страниц | 6 линий SDMMC |
| **Подсветка** | Светодиоды по краю стекла. Яркость и «теплота» задаются ШИМ — быстрым миганием | 2 линии ШИМ |
| **Кнопки** | Листание, питание, сброс | по одной линии |
| **Батарея** | Чип меряет напряжение через делитель и переводит в проценты | 1 линия АЦП |
| **Часы (RTC)** | Тикают, даже когда устройство спит | I²C |
| **Датчик** | Температура и влажность — для экрана-часов | I²C |

### Почему экран — самая сложная часть

Обычный дисплей просто получает картинку. E-ink устроен иначе: внутри плавают чёрные и белые
частицы, и чтобы их сдвинуть, на стекло подают **последовательность импульсов разного
напряжения** — это называется «волновая форма» (LUT, lookup table).

- Импульсы неправильные → изображение не зафиксируется или останутся «призраки» прошлой страницы.
- Для каждой модели стекла рецепт свой.
- Именно на этом в порте на Murphy M3 потеряли больше всего времени: то, что все считали
  таблицей импульсов, оказалось таблицей напряжений — без «удара» в начале и без выравнивания
  заряда, отсюда грязный фон.

Вывод: всё остальное — это «соединить провода в коде», а экран — единственное место,
где нужен рецепт, который нельзя угадать.

## 3. Что из ПО уже готово, а что писать

Обозначения: ✅ готово и берём как есть · ⚙️ есть, но надо настроить под наши пины ·
✍️ придётся писать · ❓ пока неизвестно

| Часть | Статус | Пояснение |
|---|---|---|
| Чтение EPUB, разметка страниц, шрифты, оглавление, закладки, прогресс | ✅ | Это и есть CrossPoint — весь смысл проекта. Ничего трогать не надо |
| Wi-Fi, веб-сервер, OPDS, синхронизация с KOReader | ✅ | Уже в прошивке |
| Работа с ESP32-S3 | ✅ | Поддержан: на нём работают X4 Pro, Sticky, de-link, M3 |
| Экран 800×480 | ✅ | Такая панель уже поддержана (X4, X4 Pro, de-link, Sticky) |
| **Контроллер экрана** | ❓ | Их бывает три вида на этой панели. Все три уже написаны — нужно лишь понять, какой у нас |
| Волновые формы (LUT) | ✅ | Идут вместе с драйвером контроллера |
| SD-карта (4 линии) | ⚙️ | Код есть, вписать наши пины |
| Кнопки | ⚙️ | Код есть, вписать наши пины |
| Подсветка тёплая/холодная | ⚙️ | Код есть (как у X4 Pro), вписать наши пины |
| Батарея | ⚙️ | Код есть, вписать пин и делитель |
| **Тачскрин FT6336U** | ✍️ | **Единственное, чего нет.** В SDK есть GT911 и CHSC6x, нашего нет |
| Часы (RTC) | ✍️ | Драйвера нет и для M3. Не мешает читать книги — можно отложить |
| Датчик температуры | ✍️ | То же самое: приятно, но не обязательно |
| Звук | ✍️ | Есть у M3 (кодек ES8388), у M4 не проверяли. Не обязательно |

### Сводка

```
   ✅ Готово ~80 %   ── чтение книг, Wi-Fi, экран этого размера, S3
   ⚙️ Настроить      ── SD, кнопки, подсветка, батарея  (заполнить пины)
   ✍️ Написать       ── драйвер тачскрина FT6336U
   ❓ Выяснить       ── какой из трёх контроллеров экрана стоит
```

## 4. Два слоя прошивки: CrossPoint и FreeInk SDK

Прошивка собирается не из одного проекта, а из двух — и это ровно то разделение, которое
делает наш порт посильным.

```
   ┌───────────────────────────────────────────────────────┐
   │  CrossPoint Reader — ПРИЛОЖЕНИЕ                       │
   │  «читалка»: полки книг, EPUB, страницы, шрифты,       │
   │  закладки, словарь, настройки, Wi-Fi, OPDS            │
   │                                                       │
   │  Не знает, к какому пину припаян экран.               │
   │  Говорит: «нарисуй эту страницу», «дай нажатие»       │
   └───────────────────────┬───────────────────────────────┘
                           │  единый API
   ┌───────────────────────▼───────────────────────────────┐
   │  FreeInk SDK — СЛОЙ ЖЕЛЕЗА (папка freeink-sdk/)       │
   │  знает про пины, шины, контроллеры, волновые формы    │
   │                                                       │
   │  display/   драйверы панелей: SSD1677, UC8253, …      │
   │  hardware/  BoardConfig, InputManager, BatteryMonitor,│
   │             SDCardManager, FrontlightManager, Rtc, …  │
   │  network/   Wi-Fi, TLS                                │
   │  ui/        готовые элементы интерфейса               │
   └───────────────────────┬───────────────────────────────┘
                           │
                    ЖЕЛЕЗО Murphy M4
```

### Зачем такое разделение

Представь, что читалку писали бы сразу «под Xteink X4». Тогда номера пинов и команды панели
были бы размазаны по всему коду, и порт на другое устройство означал бы переписывание половины
прошивки. Так и было раньше — CrossPoint начинался как прошивка ровно для одного устройства.

FreeInk SDK вынес всё «железное» в отдельный слой с простым правилом:

> **Добавить новое устройство — значит добавить данные (профиль платы и настройки драйвера),
> а не править общий код.**

Профиль платы `BoardProfile` — это и есть те самые данные: список пинов, тип контроллера
экрана, размер панели, способ чтения кнопок, параметры подсветки. Приложение об этом не знает
вовсе: оно вызывает `renderer.drawText(...)`, а SDK превращает это в импульсы на конкретных
проводах конкретной панели.

### Что это даёт лично нам

| Вопрос | Ответ |
|---|---|
| Надо ли править саму читалку? | **Нет.** Логика EPUB, страниц, шрифтов, Wi-Fi одинакова для всех устройств |
| Куда пойдут наши изменения? | Почти всё — в `freeink-sdk`: профиль M4 + драйвер тача FT6336U |
| Почему это быстро? | Панель 800×480 и ESP32-S3 в SDK уже поддержаны (X4, X4 Pro, de-link, Sticky) — берём готовое |
| Что сказал мейнтейнер | Прямым текстом: *«porting the sdk pieces over here would be ideal»* — то есть результат ждут именно в SDK |

### Где он лежит и как подключён

`freeink-sdk/` в корне проекта — это **git-сабмодуль** (отдельный репозиторий
`Free-Ink/freeink-sdk`, тоже под MIT). В `platformio.ini` его библиотеки подключены ссылками:

```ini
BatteryMonitor=symlink://freeink-sdk/libs/hardware/BatteryMonitor
EInkDisplay=symlink://freeink-sdk/libs/display/FreeInkDisplay
BoardConfig=symlink://freeink-sdk/libs/hardware/BoardConfig
...
```

Отсюда важное следствие: **правки по железу М4 коммитятся в свой форк SDK**, а не в этот
репозиторий. У тебя такой форк уже есть — `winst0niuss/freeink-sdk`, и один PR туда
(раскладки клавиатуры) уже приняли.

## 5. Как это выглядит в коде

Вся «настройка под устройство» — это одна структура на 30 строк, где перечислены пины.
Пример из SDK (профиль другого устройства):

```cpp
constexpr BoardProfile DE_LINK = {
    Board::DeLink,
    "de_link",
    InputStyle::XteinkAdcLadder,       // как читаются кнопки
    DisplayController::SSD1677,        // какой контроллер экрана
    800, 480,                          // размер панели
    {8, 10, 21, 4, 5, 6, ...},         // пины экрана: SCLK, MOSI, CS, DC, RST, BUSY
    ...                                // дальше SD, кнопки, батарея, подсветка, тач
};
```

Для M4 почти все эти числа **уже известны** — вынуты из заводской прошивки
(см. [firmware-analysis.md](firmware-analysis.md)):

| Что | Пины |
|---|---|
| Экран | SCLK=4, MOSI=3, CS=5, DC=6, RST=7, BUSY=8 |
| Тач | SDA=13, SCL=12, INT=44, питание=45 (включается нулём) |
| Батарея | АЦП на 9 |
| SD | 4 линии данных, 20 МГц |
| Панель | 800×480, кадр 48 000 байт |

## 6. Порядок работы

1. **Снять копию заводской прошивки** — страховка: что бы ни сломалось, устройство вернётся к жизни.
2. **Включить и прочитать лог** — прошивка сама печатает свои пины, сверяем с таблицей выше.
3. **Понять контроллер экрана** — и взять готовый драйвер.
4. **Заполнить структуру** пинами → CrossPoint запускается и листает книги.
5. **Написать драйвер тача** — после этого устройство полноценно рабочее.
6. Остальное (часы, датчик, звук) — по желанию.

Подробный план с командами — в [porting-plan.md](porting-plan.md).
