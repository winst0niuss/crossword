# Murphy M4 — порт CrossPoint Reader

Рабочие заметки по портированию прошивки на электронную книгу **Murphy** (она же Mofei / 摩菲, в листингах HamGeek). Целевое устройство — **M4 4.26"**, вариант 32 ГБ / Long battery, заказан на AliExpress, в пути.

Статус: **сбор информации**. Устройство ещё не получено, дампов своего экземпляра нет.
Все данные ниже — из открытых источников (см. [sources.md](sources.md)), а не из собственных измерений.

---

## 0. Главное в двух абзацах

**M4 — не «ещё один X4».** Это ESP32-S3 (не C3, как у Xteink X4/X3), с тачскрином, фронтлайтом,
USB-C с OTG и SD. Штатная прошивка от pandacat.ai («MurphyOS» / Murphy Reader v1.2.x) —
**сама является форком CrossPoint**: команда CrossPoint декомпилировала образ и нашла внутри
класс `CrossPointWebServer`, XOR-ключ из `WifiCredentialStore.cpp` и строки OPDS / KOReader Sync /
Calibre Wireless. То есть железо заведомо способно тянуть CrossPoint — вопрос только в board-профиле.

**Официального порта на M4 пока нет.** Есть работающий порт на **M3 (3.7")** и репозиторий
реверс-инжиниринга [crosspoint-reader/Murphy](https://github.com/crosspoint-reader/Murphy).
Для M4 в этом репозитории проанализирован только OTA-образ; **сырой дамп флеша ещё никто не снимал** —
это первое, что имеет смысл сделать с полученным устройством.

## 1. Путаница в названиях (читать до покупки/прошивки)

Продавцы и пользователи называют одним и тем же именем разные устройства. Классификация,
которой придерживается репозиторий CrossPoint:

| Что имеется в виду | Экран | Реальное поколение | Штатная прошивка |
|---|---|---|---|
| «Murphy 3.7», «Murphy M4 3.7», «Murphy 3» | 3.7", 416×240 | **M3** | OEM MoFei/corogoo (`touch`) |
| «Murphy M4 4.26», «Murphy 4.2» | 4.26" | **M4** | MoFei `EPD426` **или** MurphyOS (pandacat) |

Ловушки:

- В репозитории CrossPoint файл для **4.26"** (`mofei-corogoo-EPD426-v1.bin`) лежит в папке
  `m3/oem_firmware/` — как «больший брат» OEM-прошивки, а не потому что он от M3.
- Прошивка от 3.7" на 4.26" (и наоборот) даёт кирпич — на Reddit это повторялось многократно.
- Восстановление кирпича у людей срабатывало через веб-флешер `crosspointreader.com/#flash-tools`
  с заливкой custom `.bin`: держать power, нажать reset, отпустить reset, держать power всю прошивку.
  Профиль устройства подбирали перебором — на 3.7" у одних сработал **Xteink X4**, у других
  только **X4 Pro**. Для M4 подтверждённого рецепта в отзывах нет.

## 2. Murphy M4 (4.26") — целевое устройство

### 2.1 Железо

| Параметр | Значение | Достоверность |
|---|---|---|
| MCU | **ESP32-S3** | подтверждено: OTA-манифест `"chip_family": "ESP32-S3"`, заголовок образа v1.2.16 |
| PSRAM | не подтверждена (у M3 — 8 МиБ) | ? — нужен дамп |
| Flash | не подтверждён (у M3 — 16 МиБ) | ? — нужен дамп |
| Экран | 4.26" e-ink, ч/б, **~220 ppi** (уровень Xteink X4) | со слов продавца и пользователей |
| Разрешение | владелец M4 пишет «то же, что у X4» (т.е. 800×480) | одно свидетельство, дампом не подтверждено |
| Контроллер панели | неизвестен | ? |
| Фронтлайт | есть, регулировка яркости **и цветовой температуры** | подтверждено отзывами |
| Тач | есть, с настраиваемыми зонами касания | подтверждено отзывами |
| Кнопки | физические кнопки есть (в т.ч. power и утопленный reset) | подтверждено; раскладка листания не описана |
| Хранилище | microSD (16/32 ГБ в комплекте), **расширяемое** | подтверждено |
| USB | **USB-C с OTG**: режим «передача файлов» — SD видна как флешка | подтверждено |
| Wi-Fi | есть, включая точку доступа + встроенный веб-сервер (192.168.8.8) | подтверждено |
| Bluetooth / аудио | заявлены для линейки Murphy (wav/aac/mp3/flac у 3.7") | для M4 никто из отзывавшихся не проверял |
| RTC / часы | есть, экран блокировки с часами, будильник | подтверждено |
| Датчики | температура и влажность | заявлено продавцом |
| Батарея | заявлено 2000–2500 мА·ч; в отзывах есть сомнения в цифре | спорно |
| Корпус | 3D-печать (есть вариант CNC за +$2); магнита в отличие от X4 **нет** | подтверждено |
| Габариты/вес | примерно как Xteink X4, толще на ~1.5 мм, чуть тяжелее | со слов владельцев обоих |
| Цена | $54–90 в зависимости от продавца и комплектации | — |

### 2.2 Прошивки, которые существуют для M4

1. **OEM MoFei / corogoo — `EPD426-v1`.** Ветка `firmware/EPD426-v1` на
   <https://gitee.com/corogoo/3.7-inch-ink-screen-reader>; там отзывавшиеся брали v626 и v628.
   Более поздние сборки той же стоковой линейки (v631, v635, v637) раздаются уже через
   `murphy.pandacat.ai/tools/rollback`. Начиная с ~v621 починили рендеринг EPUB
   (раньше приходилось конвертировать в .txt через Calibre), появились картинки в EPUB и
   прямая подгрузка `.ttf`/`.otf` (класть в `/font`, без конвертации).
2. **MurphyOS / «Murphy Reader»** — <https://murphy.pandacat.ai/>. Это тот самый **форк
   CrossPoint** (см. ниже); проанализированная версия — v1.2.16. Сток с их страницы rollback
   бесплатен, а «Panda OS» (в отзывах фигурирует версия 2.1) — платная, ~$19. Отзывы о платной
   смешанные: жалобы на битый рендер EPUB и на то, что не нашли включение подсветки.
3. **Порт CrossPoint** — официального нет. Упоминаемые в отзывах «ported Crosspoint» сборки
   работают плохо (лаги, зависания); авторы отзывов откатывались на сток.

⚠️ **Активационный код.** При перепрошивке/восстановлении стоковой ОС устройство требует код
активации, привязанный к UID (UID виден в последнем пункте настроек, «Activate Device»).
Код выдаёт продавец на AliExpress по запросу с UID. Стоит **запросить код заранее**, до
любых экспериментов с прошивкой.

### 2.3 MurphyOS = форк CrossPoint (ключевой факт для порта)

Разбор `murphy-26-0526-1.2.16.bin` (3 903 024 байт, ESP-IDF v5.5.4, сборка 31.03.2026,
`app_offset` 131072) в [m4/findings/murphy_reader_code_reuse.md](https://github.com/crosspoint-reader/Murphy/blob/main/m4/findings/murphy_reader_code_reuse.md)
показал в бинарнике:

- строку `CrossPointWebServer` в списке активностей (имя класса из `src/network/CrossPointWebServer.cpp`);
- XOR-ключ обфускации из `WifiCredentialStore.cpp`;
- лог-строки, чья формулировка встречается только в репозитории CrossPoint;
- фичи OPDS / KOReader Sync / Calibre Wireless, которых нет в базовой MoFei-прошивке.

В OEM-образе MoFei ничего из этого нет — значит, форк произошёл уже поверх CrossPoint.

Практический вывод: **CrossPoint на этом железе заведомо запускается**, а MurphyOS —
готовый ориентир по пинам и драйверу дисплея. В репозитории лежит сам OTA-образ плюс
Ghidra-инвентарь и таблицы совпадений строк (проект Ghidra для M4, в отличие от M3, не выложен).

Отдельная находка: в MurphyOS реализован **рантайм-рендеринг `.ttf`** — разобрано в
[m4/findings/murphy_reader_ttf_fonts.md](https://github.com/crosspoint-reader/Murphy/blob/main/m4/findings/murphy_reader_ttf_fonts.md),
и есть черновик переноса этого в апстрим CrossPoint (`porting_ttf_to_crosspoint.md`).

### 2.4 Что уже сделано и чего не хватает по M4

| Есть | Нет |
|---|---|
| OTA-образ MurphyOS v1.2.16 + Ghidra-инвентарь, string-match с CrossPoint | сырой дамп флеша (никто не снимал) |
| Извлечённые ассеты веб-UI (`HomePage.html`, `FilesPage.html`, …) | карта пинов M4 |
| Доказанное родство MurphyOS ↔ CrossPoint | подтверждённые разрешение и контроллер панели |
| Разбор нативной работы с `.ttf` | board-профиль и порт |

**Ни у кого из мейнтейнеров устройства нет.** Diirge (CrossPoint Team) писал, что для порта
ему нужно получить M4 на руки; Justin Mitchell подтвердил то же 06.08.2026 (см. 2.6). То есть
первый, кто снимет дамп M4, закроет этот пробел для всех.

### 2.5 Производитель официально открыт к разработчикам

В issue [crosspoint-reader#2311](https://github.com/crosspoint-reader/crosspoint-reader/issues/2311)
(10.06.2026) от аккаунта **corogoo** команда-разработчик Murphy заявила прямым текстом:

- Murphy M4 и Murphy 3.7 **полностью открыты для разработчиков**;
- они **предоставляют полные схемы железа** и материалы по драйверу дисплея;
- фичи вроде плагинов и OPDS, которые видели в обзорах, — **не их официальная прошивка**,
  а community-порты CrossPoint (то есть pandacat/MurphyOS — сторонняя команда, не производитель);
- они хотят сотрудничать с командой CrossPoint.

Issue закрыт Justin Mitchell (`itsthisjustin`, мейнтейнер CrossPoint и автор репозитория
реверс-инжиниринга Murphy) с пометкой, что ответил им по почте.

**Практический вывод:** схемы M4 можно просто запросить у производителя через продавца или
по контактам corogoo — это дешевле, чем восстанавливать распиновку прозвонкой.

### 2.6 Ответ мейнтейнера CrossPoint (06.08.2026)

В том же issue я спросил, получил ли Justin Mitchell материалы от corogoo по почте, и можно
ли их получить ([комментарий](https://github.com/crosspoint-reader/crosspoint-reader/issues/2311#issuecomment-5208195057)).
Ответ:

> I unfortunately don't have the hardware yet but I do know there's a fork somewhere here that
> someone has working. Porting the sdk pieces over here would be ideal

Что из этого следует:

1. **Схем у мейнтейнера нет** — устройства у него до сих пор нет, и материалы от corogoo он
   не предлагает. Единственный канал за схемами — сам производитель или продавец.
2. **«Форк, где у кого-то работает»** — конкретики он не дал, и публично такого форка **нет**.
   Проверено: поиск по коду GitHub (`MurphyM4`, `murphy_m4`, `env:murphy_m4`) — ноль совпадений;
   `Uc8253Murphy` встречается только как M3-драйвер (сам SDK и его вендорные копии); среди
   39 форков `freeink-sdk` и веток `community-sdk` / `Murphy` профильная ветка одна —
   `feat-support-for-m3`. Правдоподобных объяснения два: либо он имеет в виду **MurphyOS
   от pandacat** (действительно работает на M4, но исходники закрыты и MIT их открывать не
   обязывает), либо перепутал с **форком mr-tbot**, который про M3.
3. **Куда нести результат:** «porting the sdk pieces over here» — то есть board-профиль и
   драйвер панели ждут в `freeink-sdk`, тем же маршрутом, что M3 в PR #25.

## 3. Murphy M3 (3.7") — сосед по семейству

Полезен как готовая база: на M3 CrossPoint **не просто загружается, а доведён до
работающей прошивки с готовыми бинарями**, и почти вся методика (инструменты, Ghidra,
схема анализа, board-профиль) переиспользуется для M4.

### 3.1 Железо (подтверждено дампом и прозвонкой живого устройства)

- MCU: **ESP32-S3 (QFN56) rev v0.2**, двухъядерный 240 МГц, модуль класса ESP32-S3R8:
  **8 МиБ PSRAM**, **16 МиБ flash** (quad-SPI, GigaDevice).
- USB: **нативный USB-Serial/JTAG**, `303a:1001` — отдельный мост не нужен.
- **Ни flash encryption, ни secure boot** — устройство свободно дампится и перепрошивается.
  Скорее всего то же верно для M4; это и делает план «сначала дамп» рабочим.
- Панель: Good Display **`GDEY037T03-FT21`**, контроллер **UC8253**, **240×416**, ч/б (~130 ppi).
  Фреймбуфер 240/8×416 = **12 480 байт**. Грейскейл **не работает** — рельсы VSH/VSL
  асимметричны, попытку 4 уровней серого свернули.
- Близкий родственник по железу: Elecrow CrowPanel ESP32 3.7" E-paper HMI.
- Периферия на I²C (подтверждена прозвонкой в SDK-PR #25):

  | Адрес | Устройство |
  |---|---|
  | `0x10` | аудиокодек **ES8388** |
  | `0x2e` | тач **CHSC6x** |
  | `0x32` | RTC **RX8010** (тикает; драйвера в SDK нет) |
  | `0x38` | датчик температуры/влажности **AHT30** (драйвера в SDK нет) |

- Зарядка: **TP4054**; вывод `CHRG` наружу не выведен, поэтому «идёт зарядка» определяют
  косвенно — по счётчику SOF USB-Serial/JTAG (`freeink::usbHostPresent()`).
- LittleFS + SD/MMC.

### 3.2 Карта пинов M3

| Функция | Пины |
|---|---|
| Шина дисплея (bit-bang UC8253) | `MOSI=3 SCK=4 CS=5 DC=6 RST=7 BUSY=8` (BUSY ready-high) |
| Фронтлайт | `GPIO48`, active-high PWM, 25 кГц |
| Боковые кнопки | верх `GPIO1`, середина `GPIO2`, низ `GPIO0` (active-low) |
| SD (4-битный SDMMC) | `CLK=16 CMD=17 D0=15 D1=14 D2=21 D3=18`; питание `GPIO10` **active-low** |
| Тач (I²C) | `SDA=13 SCL=12`, addr `0x2e`, INT `GPIO44` active-low |
| Гейт всей шины I²C | `GPIO43` — поднять до любого обращения к I²C |
| Питающий гейт тача и ES8388 | `GPIO45`, **active-low** |
| Батарея (ADC) | `GPIO9`, делитель 680 кОм / 680 кОм → множитель **2.0** |
| LED питания | `GPIO41` |

Грабли, на которых уже обожглись (из SDK-PR #25):

- публичные мапы CrowPanel указывают `GPIO48` как EPD BUSY — **на Murphy там фронтлайт**;
- `GPIO45` в ранних заметках числился как reset тача — **это неверно**, это питающий гейт,
  и в неправильном состоянии с шины пропадают сразу и тач, и кодек;
- `GPIO10` (питание SD) active-low: «обычная» логика оставляет карту обесточенной,
  и слот выглядит мёртвым;
- CHSC6x **не переваривает repeated-start** — чтения нужно разделять stop;
- множитель делителя батареи 3.03 (был в профиле) давал 6.3 В на заряжающемся LiPo;
- `GPIO0` — одновременно strap, кнопка confirm и кнопка питания, поэтому удержание для сна
  подняли до 1500 мс.

### 3.3 Разметка флеша M3 (16 МиБ, ESP-IDF OTA)

| Раздел | Смещение | Размер |
|---|---:|---:|
| `nvs` | `0x009000` | `0x005000` |
| `otadata` | `0x00e000` | `0x002000` |
| `app0` | `0x010000` | `0x6d0000` |

### 3.4 Статус порта на M3: есть готовая прошивка

Собранные бинарники лежат в релизе
[`murphy-m3-v1`](https://github.com/mr-tbot/crosspoint-reader/releases/tag/murphy-m3-v1)
(29.07.2026): `firmware.bin` (поверх существующей разметки, `write-flash 0x10000`) и
`firmware-full-16MB.bin` (чистая установка, `write-flash 0x0`), плюс `FLASHING.md` и SHA256.

Заявлено рабочим: EPUB со всем ридером CrossPoint (пагинация, TOC, закладки, прогресс,
словарь, OPDS, WiFi-передача, KOReader sync), MOBI/AZW с конвертацией на устройстве,
PDF с переверсткой, аудиоплеер, тач с жестами, **корректные волновые формы e-ink**,
процент батареи, индикация зарядки, фронтлайт, шрифты 5–10 pt, UI под размер панели.

Трезвые оговорки:

- сборка **неофициальная**, автор пишет прямо: «works well on my unit; no wider QA»,
  скачиваний пока единицы;
- Diirge (CrossPoint Team) о своём раннем порте: «It works. I wouldn't recommend it.
  Display is so bad» — претензия к самой панели 240×416 (~130 ppi), а не к качеству порта.

Репозиторий форка: <https://github.com/mr-tbot/Crosspoint-Murphy-M3>. Там же —
**восстановленная сообществом схема M3**: `docs/hardware/Murphy_m3_reverse_schematic_PR2.pdf`
(~530 КБ). Для M4 аналога нет, но это ровно тот документ, который нужно получить
от corogoo или восстановить самому.

⚠️ **На M4 эту прошивку ставить нельзя.** Она подогнана под панель M3 сразу на нескольких
уровнях: `Uc8253MurphyDriver` с OEM-таблицами LUT именно этого стекла, фреймбуфер
12 480 байт (у M4 при разрешении X4 было бы 48 000), принудительно отключённый грейскейл
и UI, ужатый `kUiDensityScale = 0.6`, причём шрифты 12–18 pt физически вырезаны из образа.
Ожидаемый результат — чёрный или мусорный экран; устройство при этом живо и возвращается
своим дампом. Долго гонять чужие волновые формы на другом стекле всё же не стоит.

⚠️ **Приватность дампа.** Полный дамп содержит раздел NVS с сохранёнными паролями WiFi.
Перед публикацией своего дампа M4 — вычистить NVS (`0x9000`–`0xE000`).

## 4. Что уже лежит в upstream (важно не дублировать)

⚠️ Всё это — **чужие открытые PR**. Читать и переиспользовать; свои изменения держать в форке.

### freeink-sdk (сабмодуль этого репозитория)

**[Free-Ink/freeink-sdk#25](https://github.com/Free-Ink/freeink-sdk/pull/25) — Add Murphy M3
(HamGeek M3 / 墨菲) hardware support** (OPEN, `mr-tbot`, 29.07.2026, +452/−110, 10 файлов).

Ключевое: **в SDK уже есть board-профиль `MurphyM3` и драйвер `Uc8253MurphyDriver`** — часть
подсистем была заглушена или заведена на угаданные значения, и этот PR чинит их по живому
железу. Оттуда же взяты все находки в разделе 3. Не-Murphy-специфичные части, полезные и для M4:

- `PanelDriver::supportsGrayscale()` — флаг возможностей панели (без него `displayGray`
  рисует серый план как ч/б кадр, и страница выходит почти чёрной);
- `freeink::usbHostPresent()` — определение USB-хоста без выделенного пина;
- пороги жестов, масштабируемые от диапазона координат дигитайзера, а не фиксированные пиксели;
- разделение питания/рельс тача и инициализации конкретного контроллера (раньше было
  сцеплено с веткой GT911).

Отдельно про LUT-и: то, что раньше лежало в `Uc8253MurphyLuts.h`, было **не волновыми формами,
а блоками конфигурации напряжений** (`0f8f4f…`) — без kick-фазы и DC-баланса, отсюда призраки.
Настоящие OEM-наборы вытащены из стоковой прошивки. Быстрое обновление работает **только
пакетом целиком** (вариант init `0x82=0x07`, `0x50=0xD7` + альтернативный банк LUT +
триггер `0x17`/`0xA5`); те же таблицы под mode-0 init мигают, но не фиксируют изображение.

Мейнтейнер (`itsthisjustin`) уже правил PR, чтобы не конфликтовать с другими тач-контроллерами,
и просил автора перепроверить на M3 — то есть PR в активной работе.

### crosspoint-reader (этот репозиторий)

**[#2802](https://github.com/crosspoint-reader/crosspoint-reader/pull/2802) — Murphy M3 support,
small-panel UI scaling, and native MOBI / PDF / audio** (OPEN, `mr-tbot`, 30.07.2026,
+176 879/−2 730, 100 файлов). Прикладная половина того же порта; заменяет случайно закрытый
[#2794](https://github.com/crosspoint-reader/crosspoint-reader/pull/2794). Автор прямо пишет,
что PR разбирается на части и «берите любое подмножество». Внутри:

- **масштабирование плотности UI** — метрики тем прогоняются через `scaledMetrics()` на этапе
  компиляции, один knob `kUiDensityScale` (0.6 для M3, 1.0 везде), с полом для тач-целей;
- **баг хит-теста списков, актуальный для всех устройств**: остаток пикселей под последней
  строкой не принадлежал ни одной строке, и тапы там молча терялись;
- размеры шрифта ридера **до 5 pt** + 32 новых начертания;
- `--ink-floor` в `fontconvert.py`: на 1-битной панели «слабые» пиксели не бледные, а
  **отсутствующие** — на 7 pt терялось ~20 % чернил штриха;
- **фронтлайт** как настройка (Settings → Display → Frontlight) — до этого в CrossPoint
  поддержки подсветки не было вообще;
- нативные **MOBI/AZW** и **PDF** через конвертацию в EPUB на устройстве
  (`/.crosspoint/mobi_<hash>/`, `/.crosspoint/pdf_<hash>/`);
- **аудиоплеер** на ES8388, за флагом `CROSSPOINT_AUDIO_PLAYER`.

Смежное, но полезное для нас:

- **[#2880](https://github.com/crosspoint-reader/crosspoint-reader/pull/2880) — guard against
  cross-chip firmware installs** (OPEN, `Uri-Tauber`): и SD-флешер, и OTA раньше **не проверяли
  семейство MCU** — образ для S3 можно было залить на C3 и окирпичить устройство. Ровно тот
  класс аварий, который на Reddit случался с Murphy пачками.
- **[#2472](https://github.com/crosspoint-reader/crosspoint-reader/pull/2472)** (CLOSED,
  `itsthisjustin`) — поддержка тач-устройств, ESP32-S3 и автомасштабирование UI;
  **[#2481](https://github.com/crosspoint-reader/crosspoint-reader/pull/2481)** (MERGED) —
  маппинг координат тача; **[#2675](https://github.com/crosspoint-reader/crosspoint-reader/pull/2675)**
  (OPEN) — перевод списков на FreeInkUI + масштабирование тач-UI.
- **[#2295](https://github.com/crosspoint-reader/crosspoint-reader/pull/2295)** (CLOSED) —
  battery/EPD/SD/touch для m5paper: ещё один пример S3-профиля.

**Вывод для M4:** тач, S3, масштабирование UI под другой размер панели, фронтлайт и защита от
прошивки не того чипа — уже написаны другими. Работа по M4 сводится к board-профилю
(пины + драйвер панели) поверх этого, а не к порту с нуля.

## 5. Что делать, когда устройство приедет

> Развёрнутый вариант с матрицей гипотез, профилями-кандидатами и деревом экспериментов —
> в [porting-plan.md](porting-plan.md). Ниже — короткий чек-лист.

Порядок важен: снимать дамп **до** любой перепрошивки.

- [ ] Запросить у продавца код активации по UID (пункт «Activate Device» в настройках) — на случай отката
- [ ] **Запросить у производителя схемы M4** — corogoo публично обещали их разработчикам (см. 2.5)
- [ ] Записать версию стоковой прошивки и её происхождение (MoFei `EPD426` vs MurphyOS)
- [ ] **Снять полный дамп флеша** `esptool.py read_flash 0 ALL murphy_m4_dump.bin` и сохранить в двух местах
      (хранить приватно: в NVS лежат пароли WiFi; перед публикацией вычистить `0x9000`–`0xE000`)
- [ ] Проверить, что нет flash encryption и secure boot (на M3 их нет) — иначе дамп будет зашифрован
- [ ] Зафиксировать чип и объёмы: `esptool.py flash_id`, `chip_id` (подтвердить S3, размер флеша, наличие PSRAM)
- [ ] Разобрать разметку разделов из дампа, сравнить с M3
- [ ] Определить панель: контроллер, разрешение, LUT-и (из дампа + маркировка FPC при вскрытии)
- [ ] Просканировать I²C и сравнить с картой M3 (`0x10` ES8388, `0x2e` CHSC6x, `0x32` RX8010, `0x38` AHT30)
- [ ] Восстановить карту пинов (дисплей, тач, фронтлайт, SD, кнопки, батарея) — по образцу `m3/findings/`
- [ ] Проверить наличие и объём PSRAM (влияет на всю политику памяти в CLAUDE.md)
- [ ] Посмотреть готовый профиль `MurphyM3` и `Uc8253MurphyDriver` в freeink-sdk как шаблон
- [ ] Собрать board-профиль CrossPoint под S3 и провести bring-up дисплея

Заметка по проекту: CLAUDE.md этого репозитория написан под **ESP32-C3, 380 КБ RAM, без PSRAM**.
Для S3 с PSRAM часть жёстких ограничений (одиночный фреймбуфер, запрет на `std::string`)
перестаёт быть обязательной — но менять правила проекта под M4 в общей ветке нельзя,
это должен быть отдельный board-профиль.

Организационно: вся работа ведётся **в форке** (`origin`, ветка `device/murphy-m4`).
Ничего в upstream не отправляем.
