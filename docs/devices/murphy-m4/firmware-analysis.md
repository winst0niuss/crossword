## Извлечённые константы

### Дисплей — `EPD bus up:` @ `0x42027f79`

```asm
movi   a8, 8      ; s32i a8, a1, 8    → BUSY
movi.n a8, 7      ; s32i.n a8, a1, 4  → RST
l32r   a12, "EPD bus up: SCLK=%d MOSI=%d CS=%d DC=%d RST=%d BUSY=%d @ %d Hz"
movi.n a8, 6      ; s32i.n a8, a1, 0  → DC
movi.n a15, 5     → CS
movi.n a14, 3     → MOSI
movi.n a13, 4     → SCLK
call8  0x4208a488
```

| Сигнал | GPIO |
|---|---|
| SCLK | **4** |
| MOSI | **3** |
| CS | **5** |
| DC | **6** |
| RST | **7** |
| BUSY | **8** |

Частота берётся из переменной (`a5`), константой не задана.

### Тач — `%s touch init SDA=…` @ `0x42028b65`

| Параметр | Значение |
|---|---|
| SDA | **13** |
| SCL | **12** |
| INT | **44** |
| RST | **-1** (не разведён) |
| PWR | **45** |
| PWR_ON | **0** → линия питания **active-LOW** |
| addr | из переменной (не константа) |

Контроллер — **FT6336U** (`FT6336U ready at 0x%02X` @ `0x42028f1d`); адрес читается из
структуры конфигурации. `CHSC6x` и `GT911` в образе не встречаются вообще.

### Батарея — `battery ADC ready gpio=…` @ `0x420299a7`

`gpio = 9`; `unit` и `channel` подставляются из переменных.

### SD — `SD bus pins CLK=…` @ `0x4202a051`

Аргументы: `CLK=16`, `CMD=15`, `D0=17`, `D1=18`, `D2=11`, `D3=14`, `width=4`,
`freq=20000 kHz` (0x4e20).

⚠️ К порядку D0–D3 относиться осторожно: рядом в структуру конфигурации кладутся ещё
`16, 17, 11, 21`, и сопоставление аргументов лога с физическими линиями может быть смещено.
Надёжны здесь: **4-битная шина**, **20 МГц**, и сам набор задействованных GPIO.

### Геометрия панели — `%s panel initialized:` @ `0x42026a2a`

Здесь образ сам себя идентифицирует:

```asm
movi a14, 0x1e0    ; 480
movi a15, 0x320    ; 800
l32r a8,  0xbb80   ; 48000
movi a9,  60       ; logicalStride
movi a9', 100      ; panelStride
l32r a13, "mofei"
l32r a12, "%s panel initialized: logical=%ldx%ld panel=%ldx%ld source=%ld gate=%ld
           frameBytes=%u logicalStride=%ld panelStride=%ld order=%s rotate180=%d staging=%d"
```

| Поле | Значение |
|---|---|
| logical | **480×800** (логический портрет) |
| panel | **800×480** (физический ландшафт) |
| source / gate | 800 / 480 |
| **frameBytes** | **48 000** = 800 × 480 / 8 |
| logicalStride / panelStride | 60 / 100 |
| order | `logical-portrait-to-panel-landscape` |
| rotate180 / staging | 0 / 1 |

## Главный вывод: образ — под панель 800×480, то есть под M4

`frameBytes = 48000` не оставляет вариантов: это 800×480. У M3 кадр был бы 12 480 байт
(240×416/8). Значит `panda-ai-os-2.2.7` собран для **4.26"**, и все константы выше — **пины M4**.

Заодно это независимо **подтверждает разрешение M4 = 800×480**, которое до сих пор держалось
на одном свидетельстве владельца и арифметике ppi.

### Почему пины совпали с M3

Совпадение с картой M3 (дисплей 3/4/5/6/7/8, тач 13/12/44/45, батарея 9) объясняется тем,
что **платформа общая**: одна плата под обе модели, различаются панель и корпус. Пины SPI —
это просто линии связи с контроллером панели, они не зависят от физического размера стекла.

Различие всё же есть: на M3 по данным SDK стоит тач **CHSC6x**, а здесь — **FT6336U**,
и `CHSC6x`/`GT911` в образе не встречаются вовсе.

| Подсистема | M3 (подтверждено на железе) | M4 (из этого образа) |
|---|---|---|
| Панель | 240×416, UC8253, кадр 12 480 Б | **800×480, кадр 48 000 Б** |
| Дисплей SPI | MOSI=3 SCK=4 CS=5 DC=6 RST=7 BUSY=8 | **то же** |
| Тач | CHSC6x, SDA=13 SCL=12 INT=44, гейт 45 active-LOW | **FT6336U**, те же линии |
| Батарея | ADC GPIO9 | **GPIO9** |
| SD | 4-битный SDMMC | **4-битный SDMMC, 20 МГц** |

## Опорные адреса (чтобы не искать заново)

Функция логирования — **`0x4208a488`** (вызывается через `call8`, сигнатура
`(level, tag, format, ...)`, уровень `1` во всех разобранных местах).

| Что | Строка (vaddr) | Литерал | PC вызова `l32r` |
|---|---|---|---|
| `EPD bus up:` | `0x3c37d488` | `0x420028c4` | `0x42027f79` |
| `%s panel initialized:` | `0x3c37ca34` | `0x420027d0` | `0x42026a2a` |
| `%s touch init SDA=` | `0x3c37d81c` | `0x42002974` | `0x42028b65` |
| `SD bus pins CLK=` | `0x3c37deb0` | `0x42002aac` | `0x4202a051` |
| `battery ADC ready gpio=` | `0x3c37dcc4` | `0x420029fc` | `0x420299a7` |
| `FT6336U ready at` | `0x3c37da60` | `0x42002998` | `0x42028f1d` |

Теги логов: `EPDBUS` `0x3c37d2bc`, `INPUT` `0x3c37d590`, `STORAGE` `0x3c37de4c`,
`POWER` `0x3c37dbe0`, `DISPLAY` `0x3c37c860`. Имя платформы `mofei` — `0x3c3780d0`.
Строка порядка развёртки `logical-portrait-to-panel-landscape` — `0x3c37cad0`.

## Воспроизведение

Бинарники в репозиторий не кладутся. Получить заново:

```bash
# 1. образ (сервер может отдать более новую версию — сверяйте sha256 из манифеста)
curl -s http://murphy.pandacat.ai/ota/latest
curl -sL http://murphy.pandacat.ai/firmware/panda-ai-os-2.2.7.bin -o panda227.bin

# 2. вырезать сегмент IROM (смещения — из таблицы сегментов выше)
python3 -c "d=open('panda227.bin','rb').read(); open('irom.bin','wb').write(d[0x240020:0x240020+3539980])"

# 3. дальше — скриптами из tools/
python3 tools/espimg.py panda227.bin      # сегменты, строки, литералы
python3 tools/findl32r.py                 # точки вызова
./tools/ctx.sh 0x42027f79 96 24           # дизассемблер вокруг адреса
```

Контрольные суммы разобранных образов:

| Файл | SHA-256 |
|---|---|
| `panda-ai-os-2.2.7.bin` (6 009 744 Б) | `089b10973938bdf5f05b8910853a851a1cae586ce68516a50bc4c6871e44c458` |
| `murphy-26-0526-1.2.16.bin` (3 903 024 Б) | `3ee3d0a7207a17d49eb47fa60febff8cf4ac2f47bb52d74a1beceb40b8b124ea` |

Второй лежит в репозитории `crosspoint-reader/Murphy` (`m4/`), первый раздаётся только с
сервера pandacat по HTTP — если он обновится, старую версию взять будет негде, поэтому
локальную копию стоит сохранить вне скретчпада.

## Что это значит для порта

- **Карта пинов M4 получена до приезда устройства.** Board-профиль можно писать уже сейчас.
- Остаётся неизвестным ровно одно — **контроллер панели** (SSD1677 / UC8179 / UC8279).
  Строк с именем контроллера в образе нет; определяется по init-последовательности в коде
  либо автодетектом в рантайме, как это сделано для X4 Pro.
- Профиль-шаблон — `XTEINK_X4_PRO`: та же панель 800×480, S3, тач, warm/cool подсветка, SDMMC.
- Драйвер **FT6336U** придётся написать: в `freeink-sdk` его нет.
- Serial-лог при первом включении (шаг 2 плана) остаётся полезен — как сверка, а не как
  единственный источник.
