Дата: 07.08.2026. Инструменты и метод — в [tools/README.md](tools/README.md).
Ghidra не понадобилась: хватило `xtensa-esp32s3-elf-objdump` из PlatformIO.

## Извлечённые константы

### Дисплей — `EPD bus up:` @ `0x42027f79`

```asm
movi   a8, 8      ; s32i a8, a1, 8    → BUSY
movi.n a8, 7      ; s32i.n a8, a1, 4  → RST
l32r   a12, "EPD bus up: SCLK=%d MOSI=%d CS=%d DC=%d RST=%d BUSY=%d @ %d Hz"
movi.n a8, 6      ; s32i.n a8, a1, 0  → DC
movi.n a15, 5     → CS
movi.n a14, 3     → MOSI
movi.n a13, 4     → SCLK
call8  0x4208a488
```

| Сигнал | GPIO |
|---|---|
| SCLK | **4** |
| MOSI | **3** |
| CS | **5** |
| DC | **6** |
| RST | **7** |
| BUSY | **8** |

Частота берётся из переменной (`a5`), константой не задана.

### Тач — `%s touch init SDA=…` @ `0x42028b65`

| Параметр | Значение |
|---|---|
| SDA | **13** |
| SCL | **12** |
| INT | **44** |
| RST | **-1** (не разведён) |
| PWR | **45** |
| PWR_ON | **0** → линия питания **active-LOW** |
| addr | из переменной (не константа) |

Контроллер — **FT6336U** (`FT6336U ready at 0x%02X` @ `0x42028f1d`); адрес читается из
структуры конфигурации. `CHSC6x` и `GT911` в образе не встречаются вообще.

### Батарея — `battery ADC ready gpio=…` @ `0x420299a7`

`gpio = 9`; `unit` и `channel` подставляются из переменных.

### SD — `SD bus pins CLK=…` @ `0x4202a051`

Аргументы: `CLK=16`, `CMD=15`, `D0=17`, `D1=18`, `D2=11`, `D3=14`, `width=4`,
`freq=20000 kHz` (0x4e20).

⚠️ К порядку D0–D3 относиться осторожно: рядом в структуру конфигурации кладутся ещё
`16, 17, 11, 21`, и сопоставление аргументов лога с физическими линиями может быть смещено.
Надёжны здесь: **4-битная шина**, **20 МГц**, и сам набор задействованных GPIO.

## Главный вывод: это константы M3-класса

Сравнение с картой пинов Murphy M3 (из `crosspoint-reader/Murphy` и SDK-PR #25):

| Подсистема | M3 (подтверждено на железе) | Найдено в 2.2.7 | Совпадение |
|---|---|---|---|
| Дисплей | MOSI=3 SCK=4 CS=5 DC=6 RST=7 BUSY=8 | то же | **полное** |
| Тач | SDA=13 SCL=12 INT=44, гейт питания 45 active-LOW | то же | **полное** |
| Батарея | ADC GPIO9 | GPIO9 | **полное** |
| SD | 4-битный SDMMC, CLK=16 CMD=17 D0=15 D1=14 D2=21 D3=18 | 4-битный, набор GPIO пересекается, порядок иной | частичное |

Два возможных объяснения:

1. **Образ собран под M3**, и `/ota/latest` без параметров отдаёт именно его.
2. **Платформа общая**: одна плата под обе модели, отличаются только панель и, возможно,
   тач-контроллер — тогда пины у M4 те же.

Данных, чтобы выбрать между ними, пока нет: ветка инициализации дисплея в образе **одна**
(единственная ссылка на строку `EPD bus up`), то есть двух наборов пинов в прошивке нет.

Косвенно за вариант 2: на M3 по SDK стоит **CHSC6x**, а эта прошивка умеет только
**FT6336U** — то есть образ рассчитан на железо, которое отличается от того M3, что разбирала
команда CrossPoint. Это может быть как новая ревизия M3, так и M4.

## Что это значит для порта

- **Стартовая гипотеза для M4:** пины дисплея, тача и батареи те же, что выше; отличаются
  панель (800×480 вместо 240×416) и её контроллер.
- **Проверять обязательно.** Первое же включение своего устройства с чтением Serial-лога
  (см. [porting-plan.md](porting-plan.md), шаг 2) подтвердит или опровергнет это за минуту:
  прошивка печатает ровно эти строки с реальными значениями.
- Если значения совпадут — board-профиль для M4 пишется сразу, без прозвонки.
- Драйвер **FT6336U** придётся написать в любом случае: в `freeink-sdk` его нет.
